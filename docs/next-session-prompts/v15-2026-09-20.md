## What the defect is

Not blur, not FP4, not the sampler, not a kernel. **In-context copying.**

| class | n | rank 1 | mean logprob | worst rank |
|---|---:|---:|---:|---:|
| continuation, first occurrence | 28 | 86 % | -0.699 | 19 |
| continuation, **repeat of an earlier word** | 101 | **51 %** | -3.578 | **23,989** |
| everything else | 1,371 | 88 % | -0.595 | 3,703 |

Finishing a word for the first time is healthy. Copying one the text already spelled out collapses, and the
model prefers words from *neighbouring sentences* — it retrieves the wrong thing rather than nothing. That
covers every artefact on record: `#include <stdex>`, `LRUCache` written `LRcache`, `map_._.end()`,
`std std::string`, `utfutf-8`.

This is a within-run control. It needs no reference arm, because no correct model fails to copy a word it
emitted ten tokens ago.

## What was done under v14, so it is not repeated

**The decode path was read against the reference at about forty points and matches at every one.** Window
indices, both RoPE tables and every constant feeding them, the compressed-latent positions, the compressor
at both ratios including its partial-group state and its fp32-pool-cast-then-norm ordering, the indexer's
scoring and top-k, both levels of candidate selection and the consumer's mask-before-top-k, the
sparse-attention core with its sink and its all-invalid row, the attention sink and the inverse output
rotation, the index offset and KV concatenation order, the block-diagonal `wo_a`, all three quantization
schemes, the MoE gate, the whole Engram path, and the hyper-connection sequencing and sinkhorn including its
first-step asymmetry. Details in `docs/HANDOFF-2026-09-20-quality.md`.

Two differences were found and both are benign: our sparse attention subtracts `max(row_max, sink)` where
the reference subtracts the row max, which is the same softmax; and our router returns experts ascending
where the reference returns them descending, over an order-independent sum.

**Then the attention was measured, and it retrieves correctly.** `benchmarks/attention_mass_probe.py` at two
positions two tokens apart in the same identifier:

| position | outcome | layer 3, best head |
|---|---|---|
| 331 | copy succeeds, rank 0, logprob -0.002 | 0.568 on position 319, the previous `'ator'` |
| 333 | copy fails, **rank 17,935**, logprob -18.121 | **0.928 on position 321, which is `'raits'` — the token it must emit** |

A textbook induction circuit, firing correctly, at the position that fails.

## Job 1 — follow the retrieved value forward until a stage loses it

The fault is downstream of attention and it is not a static break, because position 331 reaches rank 0
through the same output projection, MoE, hyper-connections and head. It is not token identity either:
`'cept'` and `'ip'` each appear in both the failing and succeeding sets, so the same token is reachable at
one position and buried at another.

Extend `benchmarks/attention_mass_probe.py`, which already patches the MLX `sparse_attention` and so has the
hook points. At position 333, layer 3:

1. Capture the attention **output** and confirm it is dominated by the value stored at position 321. In this
   architecture the same `kv` vector is key and value, so a 0.928 score on 321 should put that vector into
   the output almost unchanged. If it does not, the value path is the answer.
2. Follow that contribution through the inverse output rotation, `wo_a`, `wo_b`, and the `hc_post` that
   writes it back into the four residual streams. Compare each stage against the same stage at position 331,
   which works. The paired positions are the control — one model state, two outcomes.
3. If the contribution survives to the end of layer 3, walk it up the stack. Something between layer 3 and
   the head discards it at 333 and keeps it at 331.

Prefer measuring over reading: reading matched forty times and the fourth pass found the defect by
measuring. Both positions are cheap, about three minutes each.
